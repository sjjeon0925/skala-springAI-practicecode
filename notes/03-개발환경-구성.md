## 키 보관 - 개발·팀·운영

*Day 1 · 개발환경 구성*

- 키를 어디에 두는지가 첫 번째 보안 결정이다
- 단계마다 답이 다르다 - 개발은 편의, 운영은 통제
- 공통 원칙 하나 - 소스와 로그에는 절대 남기지 않는다

| 단계 | 권장 | 왜 | 주의 |
|---|---|---|---|
| 개인 개발 | VS Code launch.json · 셸 환경변수 | 소스에 안 들어간다 | 셸 히스토리에 남을 수 있다 |
| 팀 공유 | 공유하지 않는다 - 각자 발급 | 누가 썼는지 추적된다 | 한 키 돌려쓰면 사고 추적 불가 |
| CI | 저장소 Secret | 로그에 마스킹된다 | PR 빌드에는 노출 주의 |
| 운영 | K8s Secret · Vault | 회전·감사가 된다 | 환경변수 덤프 엔드포인트 차단 |

```bash
# ❌ 절대 하지 않는다
spring.ai.openai.api-key=sk-proj-abc123...      # 소스에 직접
git commit -m "설정 추가"                        # 그대로 커밋

# ✅ 환경변수로 주입 — yml 에는 자리표시만
#   application.yml :  api-key: ${OPENAI_API_KEY}
export OPENAI_API_KEY="sk-..."    # 셸에 두면 VS Code 가 그대로 물려받는다

# 이미 커밋했다면 — 히스토리에서 지워도 키는 이미 유출된 것으로 본다
#   1) 즉시 폐기·재발급
#   2) 그다음 히스토리 정리
```

## 벡터 DB - 언제 무엇을 띄우나

*Day 1 · 개발환경 구성*

- RAG 전까지는 필요 없다 - 인메모리로 충분하다
- 운영에 가깝게 해 보려면 Docker로 pgvector 한 줄이면 뜬다
- 인메모리는 재시작하면 사라진다 - 그것이 바꾸는 시점의 신호

```yaml
# docker-compose.yml — 실습 프로젝트에 포함돼 있다
services:
  pgvector:
    image: pgvector/pgvector:pg17
    environment:
      POSTGRES_DB: springai
      POSTGRES_USER: springai
      POSTGRES_PASSWORD: springai
    ports: ["5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes:
  pgdata:
```

```bash
docker compose up -d          # 띄우기
docker compose ps             # 상태 확인
docker compose down           # 내리기 (-v 를 붙이면 데이터도 삭제)
```

## 첫 실행 - 여기까지 되면 준비 끝

*Day 1 · 개발환경 구성*

- 환경 구성이 끝났는지는 한 번 돌려봐야 안다 - 컨트롤러 하나면 된다
- 여기서 막히면 다음 장으로 가지 말고 원인을 잡고 간다

```java
@RestController
class HelloAiController {
    private final ChatClient chat;

    HelloAiController(ChatClient.Builder builder) {
        this.chat = builder.build();          // 자동 구성된 빌더를 주입받는다
    }

    @GetMapping("/hello")
    String hello(@RequestParam(defaultValue = "안녕하세요") String q) {
        return chat.prompt().user(q).call().content();
    }
}
```

```bash
export OPENAI_API_KEY="sk-..."
./gradlew bootRun                # VS Code 에서는 F5 (Run and Debug)
curl 'http://localhost:8080/hello?q=Spring Boot%20AI를%20한%20문장으로'
#   → 모델 응답이 그대로 출력되면 환경 구성 완료
```

> **확인**: 응답이 한 줄 나오면 이 장의 목표는 달성이다. 여기까지 확인하고 넘어가야 이후 장에서 생기는 문제를 코드 문제로 좁힐 수 있다.

## 환경 트러블슈팅

*Day 1 · 개발환경 구성*

- 환경 단계에서 막히는 지점은 거의 정해져 있다
- 증상과 원인이 대체로 일대일이라 표로 정리된다
- 여기서 못 잡으면 뒤에서 코드 문제와 섞인다

| 증상 | 원인 | 해결 |
|---|---|---|
| 기동은 되는데 호출하면 502 | 환경변수 미설정 - 키는 부를 때 검사한다 | `export OPENAI_API_KEY=...` 후 재시작 |
| 401 Unauthorized | 키 오류·만료·결제 미등록 | 콘솔에서 키·크레딧 확인 |
| 429 Too Many Requests | 레이트 리밋 | 동시 호출 축소 · 잠시 후 재시도 |
| 한글이 깨진다 | 인코딩 불일치 | `files.encoding: utf8` · 터미널도 UTF-8 |
| 빈 주입 실패 | 메인 클래스 패키지 위치 | 최상위 패키지로 이동 |
| 임베딩만 실패 | 임베딩 모델 미설정/미다운로드 | 임베딩 모델 설정 확인 (`text-embedding-3-small`) |
| 빌드는 되는데 빨간 줄 | Java 언어 서버 캐시 | Clean Java Language Server Workspace |
| 느리다 / 응답이 없다 | 프록시·방화벽 | 사내망 프록시 설정 확인 |

> **체크**: 이 표에서 안 잡히면 대개 네트워크(사내 프록시)다. 회사망에서 외부 API가 막혀 있는지부터 확인하라 - 교육장에서 가장 흔한 원인이다.

## 실행·테스트 - 작명 봇

*Day 1 · 개발환경 구성*

- 기동 로그에 Tomcat started가 보여야 그다음이 의미 있다
- 같은 요청을 두 번 보내 본다 - 답이 달라지는 게 정상이다
- 테스트는 응답이 비어 있지 않은지부터 본다

```bash
# 1) 파일 위치
src/main/java/com/skala/lab2/NamingBot.java
#    → 실행: SpringAI_실습/03_작명봇 폴더를 VS Code 로 열고 F5 (또는 ./gradlew bootRun)

# 2) 호출
curl 'localhost:8080/lab2/name?keyword=AI,커피,야근'

# 3) 기대 결과 (매번 조금씩 다르다 — 창작이므로 정상)
1. 카페인드리븐 — 커피로 굴러가는 팀
2. 나이트올스 — 밤에 강한 팀

# 4) 고장 재현과 복구 — 이 장의 핵심 실습
unset OPENAI_API_KEY && ./gradlew bootRun     # 기동은 정상. 여기서 속기 쉽다
curl 'localhost:8080/lab2/name?keyword=AI'    # 502 + traceId  ← 여기서 드러난다
export OPENAI_API_KEY="sk-..." && ./gradlew bootRun   # 되돌리면 정상
```

## 핵심 요약 - 개발환경 구성

*Day 1 · 개발환경 구성*

- 이 장의 결론 - 필수는 셋, 나머지는 필요할 때
- 그리고 키 관리와 한도 설정이 첫 보안·비용 결정이다

| 항목 | 한 줄 정리 | 실무 포인트 |
|---|---|---|
| JDK | 21 · toolchain으로 고정 | "내 컴퓨터에선 되는데"를 막는다 |
| VS Code | 확장 팩 · UTF-8 · launch.json | 한글 깨짐 · 키 커밋을 막는다 |
| 프로젝트 | 의존성 4개면 시작 가능 | 모델 스타터는 하나만 |
| 빌드 | 래퍼로 실행 | wrapper.jar는 커밋한다 |
| API 키 | 발급 → 한도 먼저 → 보관 | 커밋했으면 폐기가 우선 |
| 임베딩 모델 | 채팅과 임베딩을 따로 설정한다 | 임베딩 누락이 실습 최대 함정 |
| 벡터 DB | 8장 전까지 인메모리로 충분 | 재시작마다 재적재면 교체 신호 |
| 첫 실행 | /hello 응답 한 줄 | 여기 막히면 진도 나가지 않는다 |
